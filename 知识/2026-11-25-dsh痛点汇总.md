# DSH 全网痛点汇总（2026-11-25 搜索）

> 来源：deepseek-harness 仓库 Discussions + 第三方文章。只作事实记录，判断在末尾。

## 一、稳定性（最高频）

1. **启动时间过长 + 工具调用陷入死循环**（Discussion #7306）——长会话启动要等很久；工具调用失败后反复重试形成死循环。
2. **安装/卸载插件能搞崩应用**（#4568）——插件生命周期管理不够隔离，装卸动作会波及引擎。
3. **dsh web 在 Windows 上工具调用 / sub-agent 触发时崩溃**（#4218）。
4. **工具调用频繁失败**（#1481）。

## 二、会话与上下文（我们自己也天天踩）

5. **Session resume 丢掉核心工具**（#10862）：恢复会话后工具注册表从 48 个掉到 19 个，有 registry-diff 证据。
6. **工具调用 id 与结果 id 不一致导致会话无法续写**：社区已有修复插件 `Semidia/dsh-session-repair-ui`（会话头部「修复会话」按钮）。
7. **pi 组件把 API 错误误判成「上下文超长」**（#4657）：误判后不触发自动重试，请求直接失败。
8. **压缩后关键细节丢失**（阿里云开发者文章）：自动压力、溢出恢复、/compact 三条触发路径行为不同，用户分不清。
9. **多轮对话到上限后无法继续，缺压缩功能**（#1933，老帖，现在已有 compaction，但仍有人不知道）。

## 三、插件生态

10. **AI 编写的 DSH 插件容易出问题**（#1884）：权限声明与实际行为不符、错误处理缺失。
11. **安全权限未生效 + 好插件用户找不到**（雷锋网转述 tool-cordis README）：插件权限系统形同虚设；发布了好插件没有曝光渠道。
12. **插件市场索引质量参差**：同一个插件多个 fork（如 dsh-purge / dsh-purge-fixed），用户不知道选哪个。

## 四、移动端 / 特殊环境

13. **dsh-go 本地引擎 getcwd ENOENT / EFAULT**（roipad 记录）：proot 环境里工作目录被删或不可达时引擎起不来。
14. **手机内存压力**：多插件 + 浏览器常驻时 OOM，实测会遇到浏览器进程被 OOM 杀掉。

## 五、我看到的规律（判断）

- **痛点集中在「状态一致性」**：会话恢复、工具注册表、插件装卸、配置热加载——全是「内存里的状态」和「磁盘上的状态」对不上。我们自己也踩过同类坑（配置被运行时覆盖），是同一个病。
- **「压缩」是第二大类**：丢细节、误判、三条路径不统一。
- **插件生态缺两样**：权限真生效、好插件有曝光。后者正好是「引流」要解决的。
- **官方修得慢的，社区用插件补**（session-repair-ui 就是例子）——说明「小补丁插件」是有真实需求的赛道。

## 对我们的启示

1. local-ops-tune 写 YAML 前必须校验——这正是「状态一致性」痛点在自己身上的体现。
2. 我们的「配置改了要重启」问题，官方也没解决（无插件重载 API），可以考虑做成插件（热重载 + 配置校验 + 回滚）。
3. 引流要给「能解决上面痛点」的东西，不是发广告。
