# 上下文压缩方案（dsh-ctxc）

> 目标：把大块输入压短，省云端 token。分工：ctxc.py=模型主动压缩大块输入；dsh-live-compact=日志尾部无模型小切；官方大摘要=兜底；会话卡=压缩后的语气校准。

## 1. 原则

1. **只做预筛，不做档案**：摘要用于省 token；原文留在原处，摘要必须带来源指针。
2. **分块压**：手机小模型吃长输入会打挂服务器——每块 ≤380 字。
3. **断点续传**：每段完成即落盘，中断重跑只补未完成段。
4. **失败不丢内容**：压缩失败，输出保留原文指针。

## 2. 工具

- scripts/ctxc.py（stdlib only）：混合并发压缩（本地 + 云端自动切换）
- 「压一下」胶囊（dsh-ctxc 插件）：剪贴板一键本地压缩回贴
- 每轮自动会话卡（dsh-ctxc 插件）：对话原话样本自动滚动

```sh
cat 长文.txt | python3 ctxc.py                  # 三点式摘要
python3 ctxc.py 文件.md --mode short            # 三句概括
python3 ctxc.py 文件.md --keep-paths            # 摘要前附来源
```

## 3. 失败与回退

- 本地 11436 不在 → 输出 `[本地压缩失败] 原文见: <路径>`，不丢内容。
- 超出本地容量 → 原样保留 + 指针。

## 4. 实测口径（手机 proot + 1.5B Q4_K_M）

- 短任务秒回；单工具 JSON 格式合规（多工具一次只认第一个）。
- 230 字以上单次长输入会把手机小模型打挂 → 分块是硬约束。
- 分块压缩：3008 字 → 1133 字（62%）。
- 断点续传：4 段中断 1 段后重跑，只补 1 段（其余复用）。
