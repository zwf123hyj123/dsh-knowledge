# 用本地小模型省 token 的完整方案

> dsh-ctxc 配套方案文档。目标：手机/低配设备上把模型成本压到最低——本地小模型扛短任务，云端大模型扛复杂任务，中间用「混合并发压缩」衔接。

## 0. 结论速览

| 场景 | 首选方案 | 预期收益 |
|---|---|---|
| 本机跑小模型 | GGUF 量化（Q4_K_M 起步） | 内存省 60-70%，速度翻倍 |
| 专用人设/工具调用 | 蒸馏到 1.5-3B | API 费接近 0 |
| 长文省 token | 上下文压缩 + KV 量化 | token 省 30-60% |
| 剪枝 | 一般不做 | 小模型上收益 < 量化 |

## 1. 量化（当天可做）

**选型参考（7B 级，手机端）**

| 量化 | 内存占用（7B 约） | 质量 | 适用 |
|---|---|---|---|
| Q8_0 | ~7.5GB | 几乎无损 | 内存富余、代码/工具调用 |
| Q5_K_M | ~5.5GB | 轻微掉点 | 性价比甜点 |
| Q4_K_M | ~4.5GB | 可用，长程推理有损 | 聊天/人设/摘要 |
| IQ4_XS | ~4.2GB | 略逊 Q4_K_M | 极限省内存 |

- 3B 级 Q4_K_M 约 2GB；1.5B 约 1GB。
- **KV cache 量化 q8_0**：长上下文内存再省一半，掉点可忽略。
- 工具：llama.cpp / Ollama。

## 2. 蒸馏（1-2 周）

- 大模型 API 当老师，蒸馏到 1.5-3B 学生模型；数据用现成对话日志 + 合成工具轨迹。
- 工具：Unsloth / LLaMA-Factory；SFT 起步，必要时加 DPO。
- 评估三件事：工具调用准确率（合成 fixture 对拍）、人设/语气一致性（用原话样本做回归）、拒答边界。
- 边界：蒸馏学人设行、学推理难——复杂任务路由回云端。

## 3. 上下文压缩（本插件的主场）

**本地压缩架构**（scripts/ctxc.py）：

- 按功能/上下文分段：标题起新段、小碎块合并，不打断语义
- 大段总结、小段原样保留（默认 ≤120 字直留）
- 断点压缩：每段完成即落盘，中断后重跑自动续传
- 超出本地容量的部分原样保留 + 原文指针，不丢内容

**dsh-ctxc 插件的两个入口**：

1. 「压一下」胶囊：剪贴板短文本本地压后回贴；超出容量自动转「当前对话云端模型压」（填指令进输入框）
2. 每轮自动滚动：每轮对话后把「用户 → 助手」原话样本滚进会话卡（校准语气用原话，不用摘要）

## 4. 落地清单

1. 装 Ollama + 拉 qwen2.5:1.5b-instruct（Q4_K_M，约 1GB）
2. 装 dsh-ctxc 插件，配置 CTXC_* 环境变量
3. 长文档走「本地摘要 + 云端」；工具输出只留要点 + 指针
4. 云端大模型只留给复杂任务

## 5. 风险与边界

- Q4 以下量化长程推理/代码掉点明显；工具调用建议 Q5_K_M 起步。
- 手机内存压力：本地模型进程可能被杀，需要保活。
- 小模型摘要是**预筛**，不是档案：关键信息保留原文指针，决策以原文为准。
