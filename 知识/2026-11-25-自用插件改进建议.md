# 自用插件改进建议（2026-11-25）

> 对象：dsh-go 原生插件目录下的 5 个自用插件（本地环境）。按「能不能马上改、改了有没有用」排序。

## 1. local-ctxc（本地上下文压缩，0.2.0）— 最值得改

现状：固定本地 qwen2.5:1.5b 压缩，块 380 字符、每块 45 tokens，串行，MAX_LOCAL 2600。

问题与改法：
1. **分层压缩**：短会话走本地，长会话（>8000 字符）走云端 deepseek-flash（1M 窗口）。现在长会话被 1.5B 小模型压成流水账，关键结论丢失率高。
2. **块间上下文**：CHUNK 切块后各块独立压缩，块间关联断掉。把「上一块输出」拼进下一块的 system，成本几乎为零，连贯性明显提升。
3. **失败回退**：本地 ollama 离线时 `compressLocal` 直接 throw，整个流程失败。应回退到「原文摘录 + 标记【未压缩】」，至少保住数据。
4. **质量自检**：压缩完从原文抽 3–5 个关键数字/专名，检查压缩结果是否包含；缺一个就在卡片上标「可能丢要点」，不自称成功。
5. **串行改并发**：块处理是 for 循环串行，2–4 并发可省一半时间（注意手机内存，别开太大）。
6. **与 dsh-ctxc 统一入口**：插件和 ctxc.py 是两套压缩，用户不知道该点哪个。建议插件只做「入口 + 展示」，压缩逻辑统一调 ctxc.py。

## 2. local-load-ease（加载优化，0.1.0）

1. **archiveTiny 直接改 workspace.json 有并发风险**：dsh 运行中写这个文件可能被引擎覆盖（实测会遇到 settings.json 被插件 flush 覆盖）。应通过 dsh API 或写前加锁 + 写后比对。
2. **recentTurn 缓存 5 分钟**：但 rescue.mjs talk 超时 240 秒，首次加载会卡很久。建议缓存延长到 30 分钟 + 后台预热。
3. **memoryList 依赖 记忆列表.json**：该文件不会自动重建，归档多了列表就旧了。加一个「扫描 sessions 目录增量重建」。
4. **compressSession 只检查 size>0**：断点压缩.py --fast 可能产出空壳。加最小长度与关键词检查。

## 3. local-ops-tune（调整面板，0.1.0）

1. **写 cordis.patch.yml 前没有 YAML 校验**：写坏一个缩进，下次启动引擎直接失败。写入前 `yaml.safe_load` 校验一次，失败回滚。
2. **没有 diff 预览**：改预设前给用户看「改哪几行」，而不是改完再说「重启引擎」。
3. **预设切换没显示当前值**：面板应标出当前是 ops-ptc 还是 standard。
4. **「提示重启引擎」可以更省事**：如果宿主支持，改成「写一个待重启标记，引擎下次空闲自动重启」。

## 4. fusion-assistant（融合助手，0.1.0）

1. **功能太杂**：解禁板、逆向分析、下载、系统设置、上下文压缩挤在一个插件里。任一功能崩溃会拖垮整个插件。建议按功能拆成 3 个独立插件。
2. **execSync 同步阻塞**：adb devices 等命令用 execSync，手机上会卡 UI 线程。改 execFile + 异步 + 超时。
3. **错误吞掉**：tap() 的 catch 只返回 toast，错误详情丢失。建议 catch 里写一行日志到文件，方便事后查。
4. **逆向/下载功能应有权限边界**：涉及外部工具调用，建议加「只在 ops-ptc 预设下启用」。

## 5. dsh-upload-boost（1.1.0）

纯配置插件，方向正确（把 client-connection body cap 一起改了，注释也写清了依赖关系）。
小建议：加一个只读状态展示「当前生效上限 = 2GB / 3GB」，省得以后忘记改没改。

## 一句话总结

最该做的是 local-ctxc 的分层压缩 + 失败回退；最危险的是 local-ops-tune 无校验写 YAML 和 local-load-ease 直写 workspace.json。
